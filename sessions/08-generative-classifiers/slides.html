Part 1

Generative vs discriminative classifiers

Two ways to answer “which class?”: model how the data is produced, or only draw the boundary.

[0:10] Theory block starts: four parts of about 15 minutes, each with an interaction.

Two strategies, one decision

Model the data, or model the boundary

🎨

Generative

Learn how each class produces data, \(p(x \mid y)\), and how common it is, \(p(y)\). Classify with Bayes' rule:

$$ \hat{y} = \arg\max_y \; p(x \mid y)\, p(y) $$

Naive Bayes, Gaussian discriminant analysis, class-conditional language models, an LLM scoring labels.

✂️

Discriminative

Learn the answer directly, \(p(y \mid x)\), without modelling \(x\) at all:

$$ \hat{y} = \arg\max_y \; p_\theta(y \mid x) $$

Logistic regression, an MLP on embeddings, a fine-tuned BERT classifier (S04).

Both end in the same place, \(p(y \mid x) = \dfrac{p(x \mid y)\,p(y)}{p(x)}\); they differ in what they spend data on.

[0:11 · 2 min] The denominator p(x) is the same for every class, so the generative classifier only needs p(x|y)p(y). A generative model can also do things a discriminative one cannot: sample new x for a class (we will do that with an LLM in Part 3), or flag inputs with low p(x). The price: it has to model x, which is often much harder than drawing a boundary.

The classic generative classifier

Naive Bayes: independence makes it cheap

Assume the words of a text are independent given the class:

$$ p(x \mid y) = \prod_{j=1}^{n} p(w_j \mid y) $$

Multinomial NB estimates each word probability by counting, with Laplace smoothing \(\alpha\):

$$ \hat p(w \mid y) = \frac{\text{count}(w, y) + \alpha}{\sum_{w'} \text{count}(w', y) + \alpha\,|V|} $$

In practice we add logs: \(\log p(y) + \sum_j \log p(w_j \mid y)\).

Why it learns fast: each class needs only word counts, estimated separately. No optimisation, no iterations.

Why it is “naive”: “price” and “target” are not independent in “price target cut”, so evidence is double-counted and probabilities become extreme.

[0:13 · 2 min] Jurafsky and Martin, chapter 4, is the reference reading for this slide. The independence assumption is false for language, yet NB is a strong baseline for short texts. The double counting matters later for calibration: NB ranks well but its probabilities are pushed towards 0 and 1 (Niculescu-Mizil and Caruana, 2005).

The classic discriminative classifier

Logistic regression: learn only the boundary

Score each class with a weighted sum of features, turn scores into probabilities with softmax:

$$ p(y = k \mid x) = \frac{\exp(w_k^\top x + b_k)}{\sum_{j} \exp(w_j^\top x + b_j)} $$

Fit \(w\) by minimising the cross-entropy (the negative conditional log-likelihood) with gradient descent:

$$ \mathcal{L}(w) = -\frac{1}{N} \sum_{i=1}^{N} \log p(y_i \mid x_i) + \lambda \lVert w \rVert^2 $$

What changes vs NB

  • Weights are fitted jointly: correlated words share the credit instead of double-counting it.
  • Needs an optimiser, iterations and regularisation \(\lambda\).
  • Probabilities are usually better calibrated than NB's.
  • A one-layer neural network: add hidden layers and you get the MLP of the lab.
[0:17 · 2 min] Jurafsky and Martin, chapter 5. Stress the last bullet: logistic regression is a neural network with no hidden layer, which is why the PyTorch MLP in the lab is a natural next step. Regularisation matters with few examples: without it, weights can grow without limit on separable data.

Theory: NB approaches its (higher) asymptotic error with about \(O(\log d)\) examples; logistic regression needs about \(O(d)\), where \(d\) is the number of features. Often two regimes: NB first, LR later.

VAEs as classifiers: learn from unlabelled data

M1 · latent features

Train a VAE on all your data, labelled or not. Encode each example into its latent mean \(\mu(x)\) and train a small classifier on those features with the few labels you have.

Same idea as our lab's MLP on sentence embeddings: a pretrained representation plus a light head.

M2 · label as a latent variable

Make the class part of the generative model: \(p(x \mid y, z)\,p(y)\,p(z)\). For unlabelled examples, \(y\) is inferred like \(z\); a classifier \(q(y \mid x)\) is trained along the way.

Kingma, Rezende, Mohamed & Welling (2014) combined M1 + M2 for strong results with very few labels.

Unlabelled data is cheap (every past email, call transcript, headline); labels are expensive. Semi-supervised generative models turn the cheap part into accuracy.

[0:32 · 2 min] Connect to S02 where students trained a VAE on Fashion-MNIST: the encoder they trained is exactly the M1 feature extractor. We do not train a VAE in today's lab; the sentence-embedding model plays the same role (a representation learned without our labels).

Zero-shot by label log-likelihood

Ask the LLM how likely each label is

A verbalizer \(v(y)\) maps each class to a word: bearish, bullish, neutral. Score each label as a continuation of the prompt:

$$ s(y) = \sum_{t=1}^{|v(y)|} \log p_\theta\big(v(y)_t \mid \text{prompt}(x),\, v(y)_{<t}\big) $$

Predict \(\hat y = \arg\max_y s(y)\); a softmax over the three scores gives a confidence.

Why score instead of generate?

  • Always returns a valid label: no parsing of “Bullish!” or “It depends…”.
  • One forward pass per label (batched), no sampling, deterministic.
  • Gives a score for every class, so you can rank, set thresholds and calibrate.
  • Works with any open model where you can read the logits.

Prompt = system message + “Tweet: … Is this tweet bearish, bullish or neutral?” rendered with the model's chat template.

[0:34 · 2 min] This is the generative classifier idea applied to an LLM: the prompt plays the role of x, and we read p(label | x) directly from the model. With an instruct model, always build the prompt with its chat template (apply_chat_template), otherwise the probabilities refer to a different kind of text than the model was tuned on.

What can go wrong

Four traps of LLM classifiers, and their fixes

1 · Surface-form competition

“bearish”, “Bearish”, “negative” share probability mass, so the right answer can lose (Holtzman et al., 2021). Fix: fix the format in the prompt, several verbalizers per class, or PMI-style scoring.

2 · Label prior bias

Models favour some labels regardless of the input (Zhao et al., 2021). Fix: contextual calibration: subtract the scores for a content-free input such as “N/A”.

3 · Prompt sensitivity

Wording, label order and few-shot examples change results. Fix: freeze the prompt like code, version it, compare variants on a dev set.

4 · Generate-and-parse fragility

Free text needs parsing and can drift. Fix: score labels, or constrain decoding to the allowed labels or a JSON schema (many APIs offer structured outputs).

[0:39 · 2 min] Holtzman, West, Shwartz, Choi and Zettlemoyer (2021) named surface-form competition; Zhao, Wallace, Feng, Klein and Singh (2021) showed majority-label and recency biases and proposed contextual calibration. The lab has a "Try it" exercise with contextual calibration. For APIs, check your provider's documentation for token log-probabilities or structured outputs; features differ by provider and change often.

Scoring labels in a dozen lines


@torch.no_grad()
def label_scores(tweet):
    prompt = prompt_ids(tweet)                   # chat template -> token ids
    scores = []
    for label_ids in LABEL_TOKEN_IDS:            # [bear, ish], [bull, ish], [neutral]
        ids = torch.cat([prompt, torch.tensor(label_ids)])
        logp = model(input_ids=ids[None]).logits.log_softmax(-1)[0]
        # the token at position t is predicted by the logits at t - 1
        pos = torch.arange(len(prompt) - 1, len(ids) - 1)
        token_logp = logp[pos, torch.tensor(label_ids)]
        scores.append(token_logp.sum().item())   # or .mean(): length-normalised
    return scores                                # argmax -> predicted label

The lab batches the three labels of a tweet into one forward pass with padding.

Prompts as classifiers

Zero-shot, few-shot and verbalizers

Zero-shot

Only an instruction and the label names. Needs no labels to start; quality depends on how well the label names describe the classes.

Few-shot (in-context)

Add \(k\) labelled examples to the prompt (Brown et al., 2020). No training, longer prompts, sensitive to which examples and in what order.

Patterns + verbalizers

PET (Schick & Schütze, 2021) rewrites inputs as cloze questions, maps labels to words, then fine-tunes on few labels plus unlabelled data.

Design the verbalizer: single, common words that the model would naturally use; avoid synonyms across classes; keep them consistent between prompt and scoring.

[0:43 · 1 min] S03 already did zero- and few-shot with generation. Today's twist is scoring. PET is the bridge between prompting and fine-tuning: it uses the verbalizer idea to squeeze more out of few labels.

Part 3

Synthetic data and calibration

Generative models can also write training data. And any classifier's confidence must be checked.

[0:46] Part 3: using the generative power of LLMs to fix class imbalance, and checking whether a model's confidence means what it says.

Synthetic data augmentation

A recipe for rare classes

  1. Seed: pick a few real examples of the rare class from the training set.
  2. Generate: ask the LLM for new, different examples (temperature ≈ 0.9, many samples).
  3. Filter: remove duplicates, near-copies of the seeds, off-format and off-label outputs.
  4. Inspect: read a sample by hand; measure diversity (for example, average similarity between examples).
  5. Train on real + synthetic; evaluate on real data only, against the real-only baseline.

Evidence: across ten classification tasks, human-labelled data matched or beat LLM-augmented data, but augmentation helped rare classes in multi-class tasks (Møller et al., 2024).

Classic alternatives: back-translation, synonym replacement, paraphrasing; see the survey by Feng et al. (2021).

[0:46 · 2 min] This is exactly Part 4 of the lab: 30 synthetic "bearish" tweets from Qwen2.5-0.5B. Møller, Pera, Dalsgaard and Aiello (2024) is a useful, sober reference: synthetic data is a supplement for rare classes, not a replacement for real labels.

Synthetic data · risks

What the generator gives, and what it hides

  • Low diversity: small models repeat the same companies and templates, so the classifier learns the template.
  • Label noise: a “bearish” request can return a bullish tweet; nobody checks unless you read them.
  • Leakage: synthetic examples in the test set inflate every metric.
  • Bias amplification: the generator's stereotypes become training data.
  • Recursion: models trained repeatedly on generated data lose the tails of the distribution (Shumailov et al., 2024).
  • Terms of use: some model licences restrict using outputs to train other models.

Calibration

Does 90% confident mean 90% right?

Reliability diagram, illustrative values: an overconfident model sits below the diagonal.

Group predictions into bins by confidence; compare accuracy and confidence in each bin:

$$ \text{ECE} = \sum_{b=1}^{B} \frac{|B_b|}{n}\, \big|\, \text{acc}(B_b) - \text{conf}(B_b) \big| $$
  • Modern deep networks tend to be overconfident; temperature scaling, \(\text{softmax}(z/T)\) with \(T\) fitted on validation data, is a simple fix (Guo et al., 2017).
  • Naive Bayes pushes probabilities to 0 and 1; logistic regression is usually well calibrated (Niculescu-Mizil & Caruana, 2005).
  • Calibration changes confidences, not the ranking: accuracy stays the same.
[0:51 · 3 min] Read the chart: the diagonal is perfect calibration. The illustrative model says "90%" but is right about 72% of the time in that bin. ECE is the weighted average gap. The lab's summary table reports ECE for every model; with small test sets it is noisy, so read it as a rough signal. Temperature scaling divides the logits by one number T fitted on validation data.

Wrap-up

Key takeaways

  • Generative classifiers model \(p(x \mid y)\,p(y)\); discriminative ones model \(p(y \mid x)\). Little data favours the first, lots of data the second.
  • An LLM is a generative classifier: score each label's log-likelihood instead of parsing free text, and watch token counts, wording and prior bias.
  • Synthetic data can help rare classes, only in training, always measured on real data.
  • Choose with macro-F1, calibration, latency, cost per 1,000 predictions and privacy, not accuracy alone.
