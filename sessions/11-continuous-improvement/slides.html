Warm-up · Q1

A credit model has the same true positive rate for men and women among applicants who repay, but approves women less often overall. Which criterion does it satisfy?

Equal opportunity asks for equal true positive rates among the people who deserve the positive outcome (Hardt, Price & Srebro, 2016). Demographic parity asks for equal approval rates overall, which fails here. When base rates differ between groups, the two criteria can conflict.

Two ways to improve

Data-centric vs model-centric

🧠

Model-centric

Hold the data fixed, iterate on the model: features, architecture, hyperparameters, loss.

Easy to automate; limited by the quality of the labels.

🗂️

Data-centric

Hold the model fixed, iterate on the data: consistent labels and guidelines, targeted collection, removing duplicates and leakage, augmentation.

Often the bigger lever for small teams (Ng, data-centric AI).

Data cascades: 92% of the 53 AI practitioners interviewed by Sambasivan et al. (2021) reported at least one compounding data problem.

Label noise

Let the model point at suspicious labels

  1. Get out-of-sample probabilities \(\hat{p}(x_i)\) with k-fold cross-validation: the model never scores an example it trained on.
  2. Self-confidence of the received label \(\tilde{y}_i\): \(s_i = \hat{p}(\tilde{y}_i \mid x_i)\).
  3. Per-class threshold \(t_j\) = mean self-confidence of the examples labelled \(j\).
  4. Flag \(i\) when another class clears its threshold with more probability than the received one.

This simplifies confident learning (Northcutt, Jiang & Chuang, 2021); their open-source library is cleanlab.

Even benchmarks have wrong labels

Northcutt, Athalye & Mueller (2021) estimated an average of at least 3.3% label errors across the test sets of 10 popular datasets.

Review, don't auto-delete: a flagged example may be a rare but correct case.
[0:25 · 2 min] This is exactly what the lab does with cross_val_predict(method="predict_proba"). Stress out-of-sample: in-sample probabilities of a model that memorised a wrong label look confident. Per-class thresholds matter because some intents are simply harder. We implement a simplified version for teaching; in a real project use cleanlab and a human review queue.

Honest numbers

Decide on validation, report on test once

Train

The model learns here. It may be noisy.

Validation

Every decision: keep or discard a change, pick hyperparameters, choose a threshold.

Test

Touched once, at the end, to report all versions. Nothing is tuned on it.

Best of 20 seeds is not a result. Run several seeds and report mean ± standard deviation; fix the seed before you start.
Is the gain real? With ~300 validation messages, one message ≈ 0.3 points of accuracy. Use a paired bootstrap or a decision threshold written in advance.
[0:31 · 2 min] Two classic sources of optimism: tuning on the test set (leakage) and picking the best of many noisy runs. Both appear in today's Crítica a la IA task. The paired bootstrap resamples the same messages for both models, so it measures the difference, not two separate noisy numbers.

Hyperparameter optimisation

Grid, random or Bayesian?

Grid search

9 trials, but only 3 distinct values of the parameter that matters.

Random search

Same budget, 9 distinct values: better when few parameters matter (Bergstra & Bengio, 2012).

Bayesian (TPE)

Uses past trials to model where good scores are and samples there next. Optuna's default sampler is TPE (Tree-structured Parzen Estimator).

Horizontal axis: the important hyperparameter; red ticks: the values actually tested.

[0:33 · 2 min] The Bergstra and Bengio argument: in most problems only a few hyperparameters matter, and grid search wastes trials repeating the same values of the important one. Random search explores more values for the same budget. Bayesian methods add memory: they learn from earlier trials.

Optuna · define-by-run

The search space is written as code


import optuna

def objective(trial):
    analyzer = trial.suggest_categorical("analyzer", ["word", "char_wb"])
    if analyzer == "word":
        n = trial.suggest_int("word_ngram_max", 1, 3)
    else:
        n = trial.suggest_int("char_ngram_max", 3, 5)
    C = trial.suggest_float("C", 0.1, 100, log=True)
    model = make_model(C, n, analyzer).fit(X_train, y_train)
    return macro_f1(model, X_valid, y_valid)   # never the test set

sampler = optuna.samplers.TPESampler(seed=42)
study = optuna.create_study(direction="maximize", sampler=sampler)
study.optimize(objective, n_trials=20)
  • Define-by-run (Akiba et al., 2019): the space can branch (word vs character n-grams).
  • Seeded sampler: the search is reproducible.
  • Pruning is early stopping for trials: report intermediate scores with trial.report and stop when trial.should_prune() says the trial is hopeless.
  • Inside one training run, early stopping watches the validation loss with some patience.
[0:35 · 2 min] Step through the highlighted lines with the arrow key. This is almost exactly the lab's code. Pruners (median, successive halving, Hyperband) matter when each trial is expensive, like fine-tuning a transformer for several epochs.

Behavioural testing · CheckList

Test capabilities, not only accuracy

MFT · minimum functionality

Simple cases with a known answer, like unit tests.

“The app is not good.” → NEGATIVE

INV · invariance

A label-preserving change must not change the prediction.

“Where is my card?” → “Where is my crad? Thanks!” → same intent

DIR · directional

A change must move the output in a known direction.

Adding “and nobody answered my calls” must not make a complaint less negative.

Pass rate = share of test cases that behave as expected. Ribeiro et al. (2020) found actionable failures this way even in extensively tested commercial models.

[0:40 · 3 min] CheckList crosses capabilities (vocabulary, negation, robustness, fairness…) with these three test types. For INV the pass rate ignores whether the original prediction was correct: it measures stability. The lab implements typos, casing, irrelevant sentences and removed punctuation in plain Python.

Distribution shift

The world moves after deployment

Covariate shift

\(p(x)\) changes, \(p(y \mid x)\) stays.

A new mobile app sends shorter messages with emojis.

Label shift

\(p(y)\) changes.

A mass card reissue triples “where is my card?” messages.

Concept drift

\(p(y \mid x)\) changes: the same input now needs a different answer.

A new policy moves pending transfers to the fraud team.

Detect: monitor input statistics and the distribution of predictions (fast, no labels needed), and performance on a labelled sample (slow, but the real signal). Huyen (2022, ch. 8); Gama et al. (2014).
[0:44 · 2 min] Ask: "Which of these has happened in your organisation?" Emphasise that the real world usually mixes the three. Behavioural tests prepare for some shifts (typos, phrasing); monitoring catches the rest.

Efficiency

Four ways to make a model cheaper to run

Quantization

Store weights (and sometimes activations) with fewer bits: int8, int4. Integer-arithmetic inference: Jacob et al. (2018); 8-bit inference for large LLMs: Dettmers et al. (2022).

Distillation

A small student learns to imitate a large teacher's softened outputs (Hinton, Vinyals & Dean, 2015). DistilBERT: 40% smaller and 60% faster than BERT, keeping 97% of its language understanding (Sanh et al., 2019).

Pruning

Remove weights, attention heads or layers that contribute little, then fine-tune to recover (e.g., Han, Mao & Dally, 2016).

Batching

Process several requests together: more throughput, but each request may wait longer. Live chat cares about latency; nightly jobs about throughput.

[0:46 · 2 min] Quantization needs no retraining (dynamic or post-training), distillation and pruning need training. The DistilBERT figures are the paper's own claims on GLUE; today's sentiment model in the lab is a DistilBERT fine-tuned on SST-2.

Quantization in one formula

Round weights to a few integer levels

Symmetric \(b\)-bit quantization of a weight tensor \(w\):

$$ s = \frac{\max_i |w_i|}{2^{b-1}-1}, \qquad q_i = \operatorname{round}\!\left(\frac{w_i}{s}\right), \qquad \hat{w}_i = s \, q_i $$

Memory of the weights

parameters × bits ÷ 8 bytes. A 7B model: 14 GB in 16-bit, 7 GB in int8, 3.5 GB in 4-bit, plus activations and cache.

When it hurts

One large outlier inflates \(s\), so small weights round to zero. LLM.int8() keeps outlier features in 16-bit (Dettmers et al., 2022); per-channel or per-group scales help too.

Dynamic quantization (today's lab) converts weights ahead of time and activations on the fly; static quantization calibrates activations; quantization-aware training learns with the rounding.

Latency is a contract

Measure on the hardware you will deploy on

Andes Bank's (fictional) live router must answer within 50 ms on shared CPUs. Before choosing a model, the team measures:

  • latency percentiles (p95, p99), not only the average;
  • size in memory: how many replicas fit per server;
  • accuracy and pass rates after compression, on the same evaluation set.

Why not trust the brochure?

  • int8 speed-ups depend on the CPU's integer kernels: on some ARM laptops dynamic int8 can even be slower.
  • Only some layers get quantized: size falls by less than 4×.
  • A smaller model can fail different behavioural tests.

Safe rollouts

Shadow → canary → A/B test

1 · Shadow

The new model sees live traffic; its predictions are logged, not used. Compare with the old one at zero customer risk.

2 · Canary

A small share of traffic uses the new model; watch errors and latency, with a rollback ready.

3 · A/B test

Random split, one primary metric, guardrail metrics, duration and sample size fixed in advance (Kohavi, Tang & Xu, 2020).

Andes Bank (fictional) A/B test for the new router. Primary: share of messages resolved without re-routing. Guardrails: satisfaction, latency p95, complaints. Version the model, data and config so a rollback takes minutes.

LLMOps

Every prompt change is a release

  • Eval suite: a versioned golden set of inputs with expected behaviour: exact checks, rubrics, LLM-as-judge calibrated against humans.
  • Regression tests run on every change of prompt, model version, tool or retrieval index.
  • Safety tests from S10: prompt injection, PII leaks.
  • Track cost, tokens and latency per request; pin provider model versions.
  • Monitor traces and user feedback; failures become new test cases.

CASES = [
    ("How do I block my card?", "lost_or_stolen_card"),

def test_router_does_not_regress():

Key takeaways

  • Improvement is a loop with a log: hypothesis → one change → validation → decision.
