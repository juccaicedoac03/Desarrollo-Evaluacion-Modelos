Warm-up · Q1

BLEU scores a machine translation against references. What is it built from?

BLEU is precision-oriented: the geometric mean of clipped 1- to 4-gram precisions, multiplied by a brevity penalty so that very short outputs are not rewarded (Papineni et al., 2002). ROUGE is the recall-oriented family; BERTScore uses embeddings.
[0:02 · 2.5 min] Common confusion: "BLEU measures recall". It does not; the brevity penalty is what compensates for the lack of recall. Ask one student to explain why a one-word translation would get a high precision without the penalty.
Warm-up · Q2

In the S05 threshold explorer, you raise the decision threshold of a classifier. What usually happens?

A stricter threshold accepts fewer cases, so the ones it accepts are usually right more often (precision up), and more true cases are missed (recall down). Today the same idea decides which customer messages a bot answers and which go to a person.
[0:05 · 2.5 min] This is the bridge. Say: "Today the threshold will not decide positive vs negative, but automatic answer vs human." Keep the phrase "fewer, safer" in mind; we reuse it.
Warm-up · Q3

You tuned hyperparameters with 5-fold cross-validation on the training data. Do you still need a held-out test set?

Every decision taken with a dataset "uses it up". Choose on validation (or CV), then report once on the test set. Today you will choose a confidence threshold exactly this way.
[0:07 · 2 min] This was one of the planted errors in the S05 challenge. Link: in the lab and the challenge, the threshold is chosen on the validation split and only reported on test.

Framing

A model is one box in a product

👤 User

Who, in which moment, through which channel? Customer, advisor, analyst?

🎯 Job to be done

The progress the user wants to make, not the feature you want to ship.

↔️ Inputs → outputs

Free text in; a label + confidence, or an answer, out. What happens next?

⚙️ Constraints

Latency, cost per request, language, privacy (Ley 1581 de 2012), regulation.

Job-to-be-done statement (Christensen et al., 2016) for Andes Bank, a fictional digital bank:

“When my card is declined abroad, I want to know why and fix it in minutes, so I can pay without calling the bank.” · “When hundreds of messages arrive on Monday morning, I want each one in the right queue, so no urgent case waits.”

In real ML systems the model code is a small part of the whole (Sculley et al., 2015).

Part 2

UX for AI

Designing for a system that will be wrong some of the time.

[0:20] Part 2, about 12 minutes: why AI UX is different, the 18 guidelines, four practices and the anti-pattern spotter.

Why it is different

Probabilistic systems need honest interfaces

  • Errors are guaranteed, not exceptional: design the failure path first.
  • Outputs vary with the input wording and, for generators, between runs.
  • Users build a mental model of what the system can do; the interface shapes it.
  • Trust must be calibrated: over-trust leads to misuse, under-trust to disuse (Parasuraman & Riley, 1997).

Initially

  2. Make clear how well it can do it

During interaction

  1. Time services based on context

  3. Support efficient correction

Part 3

Confidence thresholds and humans in the loop

When should the system answer, and when should it hand the case to a person?

[0:32] Part 3, about 24 minutes including the breakout. This is the core of the challenge's Task 1.

Selective prediction

Answer or abstain: coverage, accuracy, cost

message → classifier → confidence p → p ≥ t ?

✅ yes → automatic answer · 🙋 no → human queue

  • Coverage \(c(t)\): share of messages answered automatically.
  • Selective accuracy \(a(t)\): share of automatic answers that are right.
  • Raising \(t\): lower coverage, usually higher accuracy. This is the reject option (Chow, 1970).

Expected cost per 1,000 messages

\[ 1000\,\big[\,c\,C_{auto} + c\,(1-a)\,C_{err} + (1-c)\,C_{hum}\,\big] \]

If the confidence \(p\) is calibrated, automate when \((1-p)\,C_{err} + C_{auto} < C_{hum}\):

\[ p \;>\; t^{*} = 1 - \frac{C_{hum} - C_{auto}}{C_{err}} \]

Example: \(C_{hum}=2,\ C_{err}=15,\ C_{auto}=0.05 \Rightarrow t^{*} = 0.87\)

[0:32 · 3 min] Derive the rule aloud: for one message with confidence p, automating costs C_auto plus the error cost times the chance of being wrong (1 − p); sending it to a human costs C_hum. Automate when the first is smaller. Example: 1 − (2 − 0.05)/15 = 1 − 0.13 = 0.87. The caveat is "calibrated": we check that two slides from now. The idea of a reject option goes back to Chow (1970).

[0:35 · 5 min] Interaction. 1) Default costs (2 and 15): move the threshold and watch the U-shaped cost curve; with a calibrated model the cheapest threshold sits near t* = 0.87. 2) Raise the error cost to 50 (a wrong answer about fraud): the optimum moves right and coverage falls. 3) Lower the human cost to 0.5 (an offshore team): automation barely pays. 4) Switch to "Overconfident": the same threshold now lets more errors through, and the cheapest threshold moves up; "Underconfident" is what the lab's TF-IDF model looks like. Ask: "Who in your company would give you these three costs?" The confidences are synthetic and fixed (no randomness); expected values are computed exactly.

Calibration

Is a confidence of 0.8 really 80%?

A model is calibrated if, among the answers it gives with confidence ≈ 0.8, about 80% are right.

  • Modern neural networks are often overconfident (Guo et al., 2017).
  • In today's lab, TF-IDF + logistic regression turns out underconfident: its automatic answers are right more often than their confidence says.
  • Either way the rule \(t^*\) is off: choose the threshold empirically on validation data and report it on test.

How to check and fix it

  • Reliability table: group by confidence, compare mean confidence with accuracy.
  • Recalibrate on validation data: Platt scaling, isotonic regression or temperature scaling (CalibratedClassifierCV in scikit-learn).
  • Re-check after every model update: calibration can drift.
[0:40 · 1.5 min] Do not go deep: the message is "do not trust the formula blindly; measure". In the lab and the challenge students print a reliability table and see the gap. Temperature scaling is the simple fix proposed by Guo and colleagues; Platt scaling and isotonic regression are available in scikit-learn through CalibratedClassifierCV.
Check · threshold

A human costs 2.5 USD per ticket, a wrong automatic answer costs 10 USD and automation is almost free. With a calibrated model, from which confidence should you automate?

\(t^* = 1 - C_{hum}/C_{err} = 1 - 2.5/10 = 0.75\). Above 0.75, the expected error cost \((1-p)\times 10\) is below the 2.5 USD of a human.
[0:41.5 · 1.5 min] Give 30 seconds to compute. Follow-up: "And if the model is underconfident?" (the empirical best threshold will be lower than 0.75; measure it on validation).

Human in the loop

Design the human side too

  • What the advisor sees: the message, the top-3 suggestions, the customer's context; one click to accept or correct.
  • Sensitive intents skip automation: fraud, lost cards, legal complaints, whatever the confidence.
  • Capacity: the threshold also sets the human workload. Check it against staff and service levels.
  • Corrections become labels: the queue is your best source of new training data.
Automation bias: people tend to accept a system's suggestion even when it is wrong (Parasuraman & Riley, 1997). Audit a sample of accepted suggestions.
Aim for high automation and high human control at the same time, not a trade-off between them (Shneiderman, 2020).
[0:43 · 2 min] The human queue is a product too. If the threshold sends 30% of 50,000 monthly messages to people, that is 15,000 cases: do we have the staff? Shneiderman's two-dimensional view: reliable automation plus meaningful human control, rather than choosing one.

Latency & cost

Measure both before you choose

⏱️ Latency

  • Report the median (p50) and the slow tail (p95), not only the mean.
  • A small classifier on a CPU answers in milliseconds; a generative model or an API call takes seconds.
  • Perceived latency matters: typing indicators, streaming, “this may take a few seconds”.

💵 Cost per request

  • Own model: hosting and maintenance, almost nothing per extra request.
  • LLM or agent: tokens in + tokens out × price, or the platform plan.
  • Monthly cost ≈ conversations × turns × cost per turn. Look up current prices and date them.

In the lab you will print both latencies: the TF-IDF router and SmolLM2 or your Startti agent.

[1:04.5 · 1.5 min] As in S01, we never quote provider prices in class because they change. The point is the structure of the calculation. A hybrid design (classifier first, LLM only when needed) often wins on both latency and cost.

Wrap-up

Key takeaways

  • Start from the user and the job to be done; the model is one box among UI, router, logs and feedback.
  • Design the failure path: set expectations, show confidence usefully, fail gracefully, make the human easy to reach.
  • A threshold turns a classifier into a human-in-the-loop system: choose it by expected cost on validation data, and check calibration.
  • Gradio for fast prototypes in code; a no-code agent platform for published assistants. Measure latency and cost for both.

Exit question

In your own project, what should happen when the model is not sure? Write the exact message the user would see.
